# API contract

## Principles

- All business routes are versioned under `/api/v1`.
- Pydantic transport models are separate from domain and persistence models.
- Errors use `application/problem+json`.
- Command endpoints support idempotency where retries are plausible.
- Collection responses are paginated.
- Large artifacts are streamed.
- Public schemas are exported and checked for drift.
- The API returns no secret value or unsafe internal exception detail.

## Operational routes

```text
GET /healthz
GET /readyz
GET /api/v1/system/capabilities
```

`/healthz` reports process liveness without touching slow dependencies. `/readyz` verifies migrations, required storage, and runtime initialization. Capabilities report available runners, SQLite version, optional features, and configured limits without exposing secrets.

## Pipeline routes

```text
GET  /api/v1/pipelines
POST /api/v1/pipelines
GET  /api/v1/pipelines/{pipeline_id}
POST /api/v1/pipelines/{pipeline_id}/versions
GET  /api/v1/pipelines/{pipeline_id}/versions/{version}
```

Publishing a pipeline version validates and freezes its logical definition. Visual layout may be stored separately from the logical specification when layout changes should not create a new logical version.

## Connector routes

```text
GET  /api/v1/connectors
POST /api/v1/connectors
POST /api/v1/connectors/{connector_id}/test
```

Connector responses return secret reference names but never resolved values. Connection tests have strict time and size limits.

## Run routes

```text
POST /api/v1/runs
GET  /api/v1/runs
GET  /api/v1/runs/{run_id}
POST /api/v1/runs/{run_id}/pause
POST /api/v1/runs/{run_id}/resume
POST /api/v1/runs/{run_id}/cancel
```

Run creation captures the exact pipeline version, runner, concurrency limits, connector versions, and scenario seed. Retrying with the same idempotency key and canonical request returns the original logical response. Reusing the key for a different request returns a conflict.

## Reconciliation and repair routes

```text
GET  /api/v1/runs/{run_id}/reconciliation
GET  /api/v1/runs/{run_id}/conflicts
POST /api/v1/runs/{run_id}/repair-plans
GET  /api/v1/repair-plans/{plan_id}
POST /api/v1/repair-plans/{plan_id}/approve
POST /api/v1/repair-plans/{plan_id}/apply
```

A repair plan references one exact reconciliation fingerprint. Approval or application fails when the fingerprint is stale. Application is idempotent per action.

## Artifact routes

```text
GET /api/v1/runs/{run_id}/artifacts
GET /api/v1/artifacts/{artifact_id}
```

Artifact downloads use manifest metadata, safe content disposition, range support when practical, and strict root confinement.

## Comparison routes

```text
POST /api/v1/run-comparisons
GET  /api/v1/run-comparisons/{comparison_id}
```

Comparisons validate compatible pipeline, dataset, and canonical versions. They expose correctness first, then throughput, latency, retry, memory, queue, and database metrics.

## Durable event stream

```text
GET /api/v1/stream/runs/{run_id}
```

The SSE endpoint:

- Replays durable events after a supplied sequence or `Last-Event-ID`.
- Sends event IDs equal to durable per-run sequence numbers.
- Emits heartbeat comments while idle.
- Applies a bounded subscriber buffer.
- Disconnects slow clients rather than blocking execution.
- Allows reconnection without losing committed history.

## Live telemetry

```text
WS /api/v1/live/runs/{run_id}
```

The WebSocket carries ephemeral metrics such as queue depths, active workers, resource saturation, and short-lived timing. Loss of this channel does not affect execution and does not prevent state recovery through REST and SSE.

## Problem response

Each error contains:

```json
{
  "type": "https://paritygrid.dev/problems/invalid-transition",
  "title": "Invalid run transition",
  "status": 409,
  "detail": "A completed run cannot be resumed.",
  "instance": "/api/v1/runs/example/resume",
  "correlation_id": "...",
  "code": "run_invalid_transition"
}
```

Validation failures may include a bounded list of field errors. Internal stack traces, file paths, SQL statements, secrets, and raw upstream payloads are prohibited.

## Request rules

- JSON commands require `application/json`.
- Problem responses use `application/problem+json`.
- Upload and command sizes have explicit limits.
- Identifiers and pagination bounds are validated.
- Correlation IDs are accepted only after format and length validation or generated by the server.
- Mutating command retries use `Idempotency-Key` where documented.
- Cross-origin access is disabled by default for the packaged loopback application.

## Version coherence

Every run-related response includes:

- `run_id`
- `run_version`
- `observed_at`
- `reconciliation_fingerprint` when applicable

The frontend must reject or separately display data from incompatible run versions rather than silently merging them.

## Contract generation

- Export a stable OpenAPI document from the application factory.
- Generate TypeScript API types from that document.
- Commit both only when deterministic.
- CI rebuilds them and fails on unexplained differences.
- Every public route has success, validation, authorization if applicable, conflict, and failure tests.

## API QA

Required tests cover:

- Status and media types.
- Request and response validation.
- Problem Details shape.
- Idempotency replay and conflict.
- Pagination boundaries.
- Body and upload limits.
- SSE replay, heartbeat, reconnect, and slow consumer behavior.
- WebSocket connect, snapshot, disconnect, and malformed messages.
- Artifact root confinement.
- Static frontend fallback without intercepting API 404 responses.
